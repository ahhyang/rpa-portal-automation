RPA vs APA

Two ways to automate work — pick the right tool for the job.

RPA — Robotic Process Automation

A bot uses a real browser (or desktop UI) the way a person would: open page, type, click, scrape, screenshot.

  • Great when there is no API
  • Uses Playwright (Chromium) in this portal
  • Slower and more fragile than APIs

APA — API Process Automation

Automate by calling HTTP APIs directly: GET data, POST updates, chain steps into a workflow.

  • Faster and more reliable
  • Preferred when the system exposes an API
  • Same portal can trigger these via REST

Practice apps

Practice form · Playground (shop checkout, office inbox, ops report) — used by the complex RPA tasks.

Trigger tasks from any client

Your portal exposes a small REST API — curl, Postman, or another script can start the same automations. 

GET  /api/tasks
GET  /api/tasks/:id
POST /api/tasks/:id/run   { "inputs": { ... } }
GET  /api/runs
GET  /api/runs/:id

Example — screenshot via API

curl -X POST http://localhost:3847/api/tasks/rpa-screenshot/run ^
  -H "Content-Type: application/json" ^
  -d "{\"inputs\":{\"url\":\"https://example.com\"}}"

# then poll
curl http://localhost:3847/api/runs/<run-id>

Example — APA chain

curl -X POST http://localhost:3847/api/tasks/apa-chain/run ^
  -H "Content-Type: application/json" ^
  -d "{\"inputs\":{\"userId\":\"1\"}}"
